# OCD — OpenCode Deck

Приложение-оболочка для OpenCode на Windows 11: собственный чат, менеджер
плагинов, выбор провайдеров и гибкие настройки. Работает поверх фонового сервиса
OpenCode — то есть использует те же сессии, плагины и модели, что и штатный
OpenCode Desktop.

По умолчанию модель — `opencode/space-bunny-free`.

---

## Что умеет

**Чат**
- Полноценная работа с сессиями OpenCode: создание, переименование, удаление.
- Потоковый вывод ответов по SSE-событиям сервера (`session.text.delta` и т.д.).
- Блоки «Размышления» и вызовы инструментов — свёрнутые, с вводом и выводом.
- Несколько вкладок с сессиями, группировка по датам (Сегодня / Неделя / Месяц).
- Транскрипт перерисовывается, только когда меняется он сам: ход обёрнут в
  `memo` и не берёт из стора ничего, поэтому поток текста не перерисовывает
  всю переписку.
- Выбор модели и агента прямо в шапке чата, прерывание ответа, токены и стоимость.
- Модель фиксируется в сессии: серверный дефолт может быть недоступен в регионе,
  поэтому OCD всегда пинит выбранную модель и показывает реальную модель сеанса.
- Агент тоже принадлежит сессии, а не только следующему запросу.
- Уровень размышления — рядом с моделью: сервер отдаёт для неё варианты
  (low / medium / high / xhigh / max), и они видны в пикере.
- История не обрывается на двухстах сообщениях: страницы подгружаются вверх
  при прокрутке, положение прокрутки после подгрузки остаётся прежним.
- В шапке — ветка и число изменённых файлов: сервер считает их сам.

**Действия с сессией**
- Сжать контекст длинного разговора, ответить в другой ветке, перенести сессию
  в другой проект или в рабочую копию git.
- Команды сервера — из того же меню.
- Запомненные разрешения: что сервер запомнил и что забыть.
- Экспорт сессии в файл самого сервера и импорт такого файла — так разговор
  переносится на другую машину.

**Файлы проекта**
- Поиск файла по имени прямо в композере: кнопка и знак `@` открывают то, что
  нашёл сервер в проекте; выбранный файл прикрепляется к запросу.

**Терминал**
- Кнопка в панели композера открывает терминал ящиком снизу: команда идёт на
  сервер — там же, где идут команды агента, — а байты приходят по websocket в
  настоящий эмулятор терминала (цвета, курсор, правка строки).

**Ключи провайдеров**
- На экране провайдеров видно, какие ключи хранит сервер, какой из них
  активный, и любой можно забыть. Сам секрет на экране не показывается —
  только последние четыре символа.

**Клавиши и журнал**
- Одиннадцать сочетаний, любое переназначается или убирается в настройках.
  Сравнение точное: с лишним модификатором клавиша не срабатывает.
- Журнал приложения виден в самом приложении: поиск, копирование, кнопка
  «открыть папку». Всё, что приложение проглатывает молча, попадает туда.

**Данные от сервера, а не догадки**
- Сессии, которые сервер держит «в работе», помечены в списке: ход,
  начатый в другом окне, больше не выглядит как простой разговор.
- Откат к сообщению сначала показывает, какие файлы вернутся на место, и
  только потом применяется.
- Кольцо контекста показывает то, что сервер прочтёт на следующем ходе.
- В «Возможностях» видны ресурсы MCP-серверов, в меню сессии — журнал
  сессии от самого сервера.
- В меню экспорта — «Все сессии проекта»: архив переписок одним файлом.

**Разметка и код**
- Ответ модели рендерится как Markdown: заголовки, списки, таблицы, цитаты, ссылки.
  Заголовки смещены на уровень ниже — `#` в пузыре чата выглядел бы криком.
- Подсветка синтаксиса через highlight.js, светлая и тёмная темы.
- Номера строк в блоках кода — через CSS-счётчики, а не по одному `<span>` на строку.
- Копирование кода в один клик; внешние ссылки уходят в системный браузер.
- Код-блоки ` ```html ` получают кнопку «Открыть в панели» — смотрите ниже.
- Автоопределение языка включается только когда текст похож на исходник: иначе
  обычная английская реплика уверенно помечалась как `vbnet`, и цвета врали.

**Изменения**
- Панель «что агент поменял» прямо в шапке беседы: файлы, `+N −M`, дифф по
  клику, экспорт всего в `.patch`. Диффы берутся из `state.metadata.files` —
  сервер считает их сам при каждом вызове, который тронул файл.

**Панель предпросмотра**
- Справа от переписки: скрыта → открыта по кнопке → закреплена (переживает новый
  документ и смену сессии).
- Источники, по убыванию приоритета: файл, который вы приложили к своему запросу;
  файл, который записал агент; путь, упомянутый в тексте ответа.
- Приложенный файл открывается в панели сразу, как только вы его прикрепили, и
  показывается чипами в самом сообщении. Сервер хранит в промпте только имена
  файлов, поэтому чипы восстанавливаются из состояния приложения — после
  перезапуска переписки их не будет, останется только имя файла в тексте.
- Форматы, которые Chromium рендерит сам: HTML, SVG, PNG, APNG, JPG, GIF, WebP,
  AVIF, BMP, ICO, MP4, WebM, MOV, PDF (встроенный просмотрщик с поиском и зумом).

**Форматы**
- Word / Excel / PowerPoint / OpenDocument / RTF / CSV → LibreOffice конвертирует
  в PDF, вёрстка сохраняется.
- TIFF, PPM, TGA, JPEG 2000, EXR, PSD, PCX, DDS, HDR → ffmpeg растрирует в PNG.
- HEIC / HEIF → ImageMagick (в сборках ffmpeg нет декодера).
- **Visio .vsdx / .vsdm** → приложение читает геометрию само и рисует SVG.
  LibreOffice вообще не умеет открывать Visio: на валидном файле он отвечает
  «source file could not be loaded». Читается первая страница; рисуются геометрия,
  заливка, прозрачность, поворот и подписи фигур. Не рисуются мастер-фигуры,
  склейка коннекторов и вёрстка текстовых блоков — чертёж выходит схематичным.
  `.vsd` (старый двоичный формат) не поддерживается: это не ZIP-пакет.
- Конвертация кэшируется по времени изменения файла, временные копии чистятся
  через сутки.
- Если конвертера нет — понятное сообщение вместо ошибки.

**Безопасность предпросмотра**
- Гость — `<webview>` на выделенной партиции `persist:ocd-preview`; preload
  вешается на неё через `will-attach-webview`, поэтому ни один будущий webview
  его не унаследует.
- Наружу — только доверенный клик по ссылке `_blank`; `isTrusted` нельзя подделать
  из скрипта страницы. Проверка схемы — в главном процессе (`file:` и
  `javascript:` отклоняются).
- `allowpopups` не выставлен: гость не может открыть окно.

**Особенности протокола OpenCode, которые важно знать**
- `POST /api/session/{id}/prompt` не выполняет ход синхронно, а ставит его в inbox.
  Сообщение, отправленное во время активного хода, доставляется как *steer* —
  OCD предупреждает об этом, чтобы не казалось, что запрос пропал.
- Тело `prompt` запрещает неизвестные поля (`additionalProperties: false`):
  `model` там не принимается, модель меняется через `POST /api/session/{id}/model`.
- `agents` — массив объектов `{ name }`, а не строк.

**Плагины**
- Список реально загруженных плагинов (встроенные + локальные + npm).
- Установка из npm прямо из окна приложения.
- Кнопка «Обновить все» — сервер сам приводит установленные плагины к свежей версии.
- Подключение своих локальных плагинов из папки.
- Удаление плагина, показ папки в проводнике.
- Всё пишется в `plugins` массив `opencode.jsonc` с сохранением форматирования.

**Провайдеры и модели**
- Полный список провайдеров и моделей с сервера OpenCode.
- Статус авторизации, контекстное окно, признак reasoning.
- Поиск и фильтр, выбор модели по умолчанию.
- Локальные движки (Ollama, LM Studio) — переключаются; список движков
  спрашивается у машины, а не зашит в приложение.

**Файлы проекта**
- Отдельный экран с деревом проекта — так, как его видит сервер: те же
  папки, те же пути, те же файлы, что получает модель.
- Содержимое читается лениво, только при выборе файла; бинарное и слишком
  большое открывается в редакторе системы.
- Вкладка «Изменения» — настоящий diff рабочей папки, посчитанный git, а не
  собранный из вызовов агента.

**Один разговор, на стороне сервера**
- Переменные окружения: значения достаются только командам этого разговора.
- Инструкции разговора: текст, который сервер добавит к этой беседе.
- Фоновый режим: долгие команды уходят в фон, разговор остаётся свободным.

**Возможности**
- Агенты, команды, навыки, MCP-серверы — в одном месте.
- MCP-серверами можно управлять: подключить, отключить, убрать.
- Видно, какой провайдер веб-поиска у сервера.

**Поиск**
- Фильтры по модели, проекту и дате поверх полнотекстового индекса.
- Переход к найденному сообщению: открывается нужная беседа и курсор
  встаёт на сообщение, в котором нашлась фраза.
- Индекс перестраивается по кнопке, когда он разошёлся с сервером.

**Шаблоны**
- Свои заготовки для запросов: пишутся один раз и вставляются в поле с
  отмеченными местами под свои значения.

**Вложения**
- Вставка из буфера обмена (`Ctrl+V` с изображением) и кнопка вставки.
- Drag-and-drop файлов в любое место окна.
- Кнопки: изображение / любой файл.
- Изображения до 8 МБ уходят инлайн как `data:` URL, крупные и остальные файлы — по `file://`.
- Поддерживаются изображения, видео, аудио, документы (pdf, txt, md, json, csv) и любые другие файлы.

**Отправка и остановка**
- Кнопка отправки и кнопка остановки разделены: во время активного хода
  можно либо остановить его, либо отправить уточнение — оно доставляется как *steer*
  и попадает в текущий ответ.
- Если модель зависла и сервер не прислал ни завершения, ни ошибки,
  состояние «в работе» само сбрасывается через 5 минут.

**Голос и диктовка**
- Озвучивание ответов через `edge-tts` (голос `ru-RU-SvetlanaNeural` по умолчанию),
  офлайн-фолбэк — системный голос Windows (SAPI).
- Список голосов и громкость — в настройках; голоса читаются у движка, а не
  зашиты в приложение.
- Диктовка в поле ввода: запись с микрофона → `faster-whisper` (локально).
- Настройки голоса наследуются из ваших плагинов `oc-voice` / `oc-dictate`.

**Внешний вид**
- Настоящий системный фон Windows 11: Mica Alt — тот же материал, из которого
  сделано окно папки в Проводнике (`backgroundMaterial: "tabbed"`). Акрил с
  размытием — рядом, в настройках.
- Светлая тема в стиле Mica (как Проводник) и тёмная.
- Настройка материала фона, плотности оттенка, акцента, размера шрифта.

## Требования

| Что | Зачем |
|---|---|
| Windows 11 22H2+ | системный фон (Mica Alt); на более старых окно будет полупрозрачным без фона |
| OpenCode 2.x, запущенный как фоновый сервис | OCD подключается к нему по HTTP |
| Python 3 + `edge-tts`, `faster-whisper`, `sounddevice`, `numpy` | только для голоса и диктовки |
| `ffplay` (входит в полный fffmpeg build) | воспроизведение озвучки |
| `ffmpeg` | растеризация tiff/ppm/tga/jp2/exr/psd/pcx/dds/hdr |
| ImageMagick 7 (Q16) | **HEIC/HEIF/AVCI** — ни одна сборка ffmpeg из winget не содержит libheif |
| LibreOffice | doc/xls/ppt/odt/ods/odp/rtf/csv → PDF для предпросмотра |
| OpenSSH Client (входит в Windows 11) | туннель к удалённому OpenCode |

Без Python приложение работает полностью — голос просто отключится.

Установка Python-зависимостей:

```powershell
python -m pip install edge-tts faster-whisper sounddevice numpy
```

```powershell
npm install
npm run dev      # разработка с hot reload
npm run build    # сборка в out/
npm start        # запуск собранной версии
npm run typecheck
```

## Сборка .exe

```powershell
npm run dist     # release/OCD Setup 3.x.x.exe + OCD-portable-3.x.x.exe
```

`extraResources` кладёт `resources/voice.py` и иконку рядом с exe.

`npm run pack` собирает распакованную папку (`release/win-unpacked`) — она
удобна для проверки на месте. Такой сборке нужен файл канала обновлений
`resources/app-update.yml`: установщик его кладёт сам, а `npm run pack`
дописывает его отдельным шагом. Без него приложение спрашивает обновления и
получает `ENOENT` — и молчит.

## Как OCD находит OpenCode

1. Читает регистрацию фонового сервиса:
   `$XDG_STATE_HOME/opencode/service.json` или `~/.local/state/opencode/service.json`
   (`{ id, version, url, pid, password }`).
2. Если сервис не отвечает — поднимает `opencode serve --service`,
   ищет бинарник в `PATH`, затем в `%APPDATA%\ai.opencode.desktop\cli\*\opencode-cli.exe`.
3. Авторизация — HTTP Basic (`opencode` + пароль из регистрации).
4. В адресной строке настроек можно указать свой адрес сервера.

Адрес можно открыть сразу на нужном экране: `OCD.exe` поддерживает
`#settings`, `#plugins`, `#providers`, `#capabilities`, `#about`, `#chat`.

## Возможности

### Панель предпросмотра

Кнопка-куб в шапке чата (или «Открыть в панели» на блоке ```html) показывает документ
рядом с перепиской. Панель открывается сама, когда модель отдаёт HTML-блок или созданный файл.

Маршруты: нативно (HTML/SVG/изображения/видео/PDF) → LibreOffice → PDF → растеризация
(ffmpeg, затем ImageMagick). Результат кэшируется по времени изменения файла, чистится через сутки.

Гостевая страница грузится в <webview> на партиции persist:ocd-preview; preload вешается
только на неё. Внешние ссылки открываются в системном браузере и только по доверенному клику.

### Поиск по содержимому бесед

Сервер OpenCode не имеет поиска, поэтому индекс строится на стороне OCD: сообщения всех сессий
читаются один раз и складываются в ocd-search-index.json рядом с настройками. Поиск по названию
мгновенный, по тексту — с задержкой 180 мс. Совпадения показываются отдельным блоком с фрагментом.

Индекс пересобирается при изменении сессии; удалённые сессии из него выбрасываются.

### Трей, горячая клавиша, окна сессий

- Трей: показать/скрыть, быстрый запрос, недавние сессии, статус сервера, перезапуск,
  язык интерфейса, HUD, выход. Всё переведено на 5 языков.
- Глобальная горячая клавиша (по умолчанию выключена, задаётся в настройках) показывает окно
  и ставит курсор в поле ввода. Занятая другим приложением клавиша сообщается честно.
- Любую сессию можно открыть в отдельном окне: #session/<id>, одно окно на сессию.

### Экспорт беседы

Markdown, HTML и PDF. Инструменты сворачиваются в строки вида цитаты с названием команды,
рассуждения отбрасываются — в экспорте остаётся разговор, а не журнал. PDF печатается
скрытым offscreen-окном.

### Панель задач

Читает чекбоксы из последнего ответа модели и показывает прогресс. Это отображение плана,
а не отдельный список: разойтись с текстом модели он не может.

### Изменения и диффы

У сервера нет ни эндпоинта «что изменилось», ни истории версий. Зато в каждом
вызове, к которому прикасался файл, лежит сам патч: `state.metadata.files` —
`{ file, patch, status, additions, deletions }`. Это единственный источник, у
которого есть состояние файла *до* запуска вызова, поэтому только в нём видны
удаления при перезаписи файла целиком. Панель читает его первым делом, а сама
собирает дифф лишь когда патча нет.

- В шапке беседы — счётчик вида «3 файла +240 −31», раскрывается списком файлов.
  У каждого: сколько вызовов его трогали, `+N −M`, статус (создан / изменён /
  удалён), кнопка «патч» (копирует unified diff) и открыть: файлы, которые умеет
  показывать панель предпросмотра, идут в неё, остальные (то есть почти весь
  код) — в редактор системы.
- Разворачивается файл — дифф: номера строк с обеих сторон, добавленные зелёным,
  удалённые красным. Номера идут через CSS-счётчики, как в блоках кода: одна
  строка разметки на строку файла при перезаписи всего файла — это тысячи узлов
  ради двух чисел.
- Несколько вызовов одного файла идут подряд: их патчи уже посчитаны против
  реального состояния, поэтому склеиваются в один блок, и это по-прежнему
  точная история файла.
- Вызовы `edit` / `write` в самом чате показывают свой дифф вместо JSON: то, что
  агент изменил, и есть ответ. Исходный вызов остаётся под ним, в свёртке.
- «Сохранить .patch» пишет всю беседу одним unified diff, готовым для
  `git apply`. Серверные патчи уходят байт в байт; пересобираются только те, что
  пришлось посчитать самим, и им обрезается контекст до трёх строк — иначе
  однострочная правка превращается в патч на весь файл.

Запасной путь — для серверов, которые патч не присылают: дифф восстанавливается
из `oldString` / `newString`, а если цепочка рвётся — показывается отдельными
блоками, с честной пометкой. Тот же случай у `write` без патча: файл помечен
«записан целиком», видно написанное, но не видно удалений.

### HUD

Небольшая полоска поверх окон: что модель делает прямо сейчас. По умолчанию выключена,
включается из трея или настроек. Состояние собирает main и передаёт в окно HUD.

### Удалённый OpenCode по SSH

Настройки → «Удалённый сервер (SSH)»: хост в формате user@host и порт OpenCode на сервере.
Приложение поднимает туннель системным OpenSSH и переключает сервис на локальный порт.
Пароли не передаются: используются ваш ~/.ssh/config и ssh-agent.

### Расход, уведомления, правки

- **Расход** — стоимость и токены в шапке беседы, раскрываются кликом. Считается и по
  сохранённой истории, и в реальном времени через событие `session.usage.updated`.
- **Уведомления** — Windows-toast, когда ход закончился, пока окно свёрнуто. Плюс мигание
  панели задач. Отключаются в настройках.
- **Правка промпта** — кнопка «Изменить» на своём сообщении возвращает текст в поле ввода.
  Удалить сообщение и перезапустить ветку нельзя: сервер не даёт такой API (DELETE по
  сообщению и все разумные маршруты revert отвечают 404).
- **Фильтр инструментов** — по умолчанию показывает только неуспешные и текущие вызовы,
  остальные сворачивает в строку со счётчиком.
- **Черновики** — неотправленный текст хранится по беседе и переживает закрытие вкладки.
- **Закрепления и заметки** — важные ответы и своя заметка по беседе, локально, модель их
  не видит. Переживают перезапуск.

### Командная палитра

Ctrl+K — команды и беседы в одном списке. Поиск по названию и по словам-подсказкам,
стрелки и Enter.

### Перенос сообщений

Кнопка на сообщении копирует обмен в буфер с меткой; в целевой беседе Ctrl+V подставляет
её в поле ввода. Сервер не умеет двигать сообщения, поэтому текст остаётся под контролем
пользователя.
### Автообновление

Выключено по умолчанию, работает только в установленной сборке. В настройках три
шага, каждый по кнопке: «Проверить сейчас» находит версию, «Скачать обновление»
кладёт её в кэш обновлятеля, «Установить и перезапустить» запускает установщик и
перезапускает приложение. Скачивание само не начинается никогда — 110 МБ не
должны уезжать без спроса.

Пока версия найдена и не установлена, на иконке окна и в трее горит стрелка
(`icon-update`) — тем же приёмом, что и здесь, в OpenCode. Значок снимается сам
после перезапуска на новой версии.

В шапке окна слева от кнопок управления появляется круглая стрелка: она читает
состояние обновления из главного процесса (опрос раз в минуту и при фокусе
окна) и делает всё за один клик — скачивает, затем ставит и перезапускает.
Стрелка появляется только если обновление действительно найдено, то есть при
включённой автопроверке либо после ручной проверки в настройках.

Автопроверка при запуске молчит: нашла версию — стрелка на иконке и кнопка в
шапке, не нашла — тоже стрелки нет и сообщения нет. Модальные окна остались
только у событий, которые приходят сами (например, если включить автозагрузку),
а ручные кнопки в настройках отвечают тостом из своей же функции — диалог поверх
него просто повторял то же самое.

### Обратная связь и счётчик установок

На экране «О программе» есть карточка, куда можно написать пожелание, претензию
или сообщение об ошибке: тема, текст, необязательное поле «Куда ответить» и
галочка «Приложить сведения о сборке». Рядом — ссылка на профиль автора, она
работает и когда отправка не настроена.

Отправка идёт в веб-приложение на Google Apps Script, которое пишет строки в
таблицу. Развернуть его — 15 минут, инструкция в
[`scripts/feedback-endpoint/README.md`](scripts/feedback-endpoint/README.md),
сама таблица и приёмник — рядом, в `Code.gs`. Пока `BACKEND_URL` в
`src/main/feedback.ts` пустой, приложение ничего не отправляет, а карточка
пишет об этом прямо на экране.

Отдельно от отзывов приложение один раз на версию сообщает, что она установлена.
Это и есть ответ на вопрос «скачал ли кто-нибудь кроме автора»: счётчики
GitHub Releases для этого не годятся — там основной трафик это проверки
обновлений у самого автора.

Считаются не запуски, а машины: в `%APPDATA%\OCD\ocd-feedback.json` лежит
случайный `installId`, а список уже отмеченных версий — рядом с ним. Машина,
обновившаяся с 0.1.1 до 0.1.13, пишет тринадцать строк и считается один раз.
Ответ приёмника на `<url>/exec` — тот самый счётчик:

```json
{ "ok": true, "uniqueInstalls": 1, "marks": 13, "perVersion": { "0.1.13": 1 }, "feedback": 0 }
```

Уходит только это: идентификатор машины, версия приложения, система, архитектура,
версия Electron и язык. Ни путей, ни имён файлов, ни переписки. Журнал
`ocd.log` прикладывается лишь по галочке и обрезается до 20 000 символов.

### Как выпустить релиз

Канал обновлений — GitHub Releases репозитория `Sergey35853/ocd`.

```bash
npm version patch              # 0.1.0 -> 0.1.1: коммит + тег
git push origin main --follow-tags
```

Тег `v*` поднимает `.github/workflows/release.yml`: сборка на `windows-latest` и
публикация в релиз. electron-builder кладёт рядом `latest.yml` и `.blockmap` — без
них установленная копия обновление не найдёт, поэтому руками релиз не создаём.

electron-builder по умолчанию делает релиз **черновиком**, а черновики обновлятель
не видит. Поэтому в `build.publish` стоит `releaseType: release`: без него релиз
соберётся, пройдёт все шаги и молча останется невидимым.

Локально (когда CI не подходит) — то же плюс токен в `GH_TOKEN`:

```bash
npm run dist
```

Подпись сборок не настроена: каждый новый установщик вызывает предупреждение
SmartScreen. На само автообновление это не влияет. Portable-сборка
(`OCD-portable-*.exe`) не обновляется — только установщик NSIS.

## Безопасность

- `contextIsolation: true`, `nodeIntegration: false`, весь доступ к диску и сети — через IPC в main.
- Открытие внешних ссылок только для `http(s)`.
- Правка `opencode.jsonc` — с валидацией и бэкапом.
- Markdown рендерится с `html: false`, а единственное место, где в DOM попадает
  разметка — подсветка, и там текст экранируется заранее.
- Гость предпросмотра изолирован партицией и не имеет доступа к IPC.
- Из приложения уходят ровно два события: отметка об установленной версии (id
  машины, версия, система, архитектура, Electron, язык) и отзыв с экрана «О
  программе». Отметка не содержит ничего, что человек писал, — это проверяется
  тестом; журнал приложения уходит только вместе с явной галочкой. Событий не
  будет вовсе, пока пуст `BACKEND_URL`.

## Зависимости

Встраиваются в `node_modules`, поставляются вместе с exe:

| Пакет | Зачем |
|---|---|
| `markdown-it` | Markdown-рендер ответов |
| `highlight.js` | подсветка синтаксиса |
| `jsonc-parser` | правка `opencode.jsonc` без потери комментариев |

Внешние программы для предпросмотра (не обязательны):

| Программа | Зачем | Без неё |
|---|---|---|
| LibreOffice | Word / Excel / PowerPoint → PDF | сообщение «не найден LibreOffice» |
| ffmpeg | TIFF, PSD, JPEG 2000 и прочие → PNG | сообщение «не найден ffmpeg» |

Пути к обоим перебираются в стандартных местах установки и в `PATH`; положите
`ffmpeg.exe` в `PATH`, если он установлен нестандартно.
